## 2. Naming audit

### Option A: metadata only (low risk)

Change only what does not touch the bench app name:
1. `package.json` name → `paypilotlabs-crm`, plus description, homepage, repository, bugs, licence (B7).
2. `frontend/package.json` name → `paypilotlabs-crm-ui`.
3. `pyproject.toml` description and `[project.urls]` → PayPilotLabs (B8). `[project] name` stays `crm`.
4. `hooks.py` `app_description` from `brand.py` (B4).

Files touched: `package.json`, `frontend/package.json`, `pyproject.toml`, `crm/hooks.py`, `crm/brand.py`. App stays `crm`; routes, imports, assets, Docker, other repos unchanged. Users see no difference except correct text.

### Option B: full app rename to `paypilotlabs_crm` (high risk)

1. `git mv crm paypilotlabs_crm`; `[project] name`, `hooks.app_name`, `__init__` → `paypilotlabs_crm`.
2. Rewrite every `crm.` import and dotted method path: ~110 .py files, `hooks.py` (all doc_events, scheduler, overrides, `has_permission`), `patches.txt`, doctype/report JSON, frontend `frappe.call`/`createResource` URLs (`crm.api.*`), `crm/public/js/*`.
3. Every `/assets/crm/` path (10 files) and `vite.config.js` build paths.
4. `docker-compose.yml` `--install-app`, `.github/scripts/check_independence.py` `PACKAGE`, CI `compileall crm`, Playwright/e2e config.
5. Existing sites cannot be upgraded in place: bench sees a new app. Every site needs a data migration (rename `tabInstalled Application`, `Module Def.app_name`, patch log entries) or a fresh install.
6. Every merge from upstream frappe/crm becomes a large manual conflict.
7. Keep routes at `/crm` (no redirect work).

Files touched: all 498 tracked files under `crm/` move; about 120 to 150 files get content edits.

### Recommendation

**Option A.** Users never see the app name `crm`; they see "PayPilotLabs CRM" in titles, emails, the workspace and the app screen, which is already done. Option B costs a day of edits, breaks upgrade paths and upstream merges, and changes nothing a customer sees. Keep `/crm` as the route.
